# 01 · 产品定义与用例

## 1. 平台要解决的四个痛点

当前维护 witty-agents 流水线，事实分散在四个地方，且都需要"记得住地址 + 有服务器权限"：

| 痛点 | 现状 | 平台对策 |
| --- | --- | --- |
| 构建状态不透明 | 只能登录 Jenkins 控制台看 Job 列表，红蓝混在一起（`witty-agents ci`、`witty-ub-build` 的红色与主流水线无关） | 只纳管本项目 Job，把"与本流水线无关的红"隔离掉 |
| 失败定位成本高 | 日志里 Jenkins 的 ANSI 着色码会淹没有效信息；失败原因藏在归档 JSON 里 | 阶段视图 + 日志高亮 / 错误导航 + 报告 JSON 结构化呈现 |
| 发布风险不可见 | npm `latest` 曾指向测试版本；dist-tag 变更无历史；SHA-256 校验失败只能翻日志 | 发布门禁清单、发布链路时间线、dist-tag 历史与回滚 |
| 操作无留痕 | 谁触发了构建、谁改了默认参数、谁确认了发布，只在 Jenkins 里留一行 name | 全量审计 + AI 操作「用户 × Agent」标记 |

## 2. 使用者与角色

平台共 4 个角色，与原型 `users.html` 的权限矩阵一致（原型用"视角切换"演示，平台按登录身份真实生效）。

| 角色 | 说明 | 典型人员 |
| --- | --- | --- |
| 系统管理员 | 管用户、管全局配置（Jenkins 绑定、凭据引用） | 平台负责人 |
| 项目管理员 | 管项目成员、项目配置、发布与回滚 | witty-agents 维护者 |
| 开发成员 | 触发构建、看日志、下载产物；不能改发布参数 | Agent 开发者 |
| 只读访客 | 只读视图（可看构建与发布，不能触发/下载受限产物） | 其他团队 / 评审人 |

与 Jenkins 账号的关系：平台账号独立于 Jenkins 账号。平台后台使用 **一个** Jenkins 服务账号 + API Token 访问 Jenkins API，权限按 Matrix 最小权限矩阵授予（见 [07](07-pipeline-integration.md) §12），平台用户不直接持有 Jenkins 凭据。

## 3. 权限点定义

平台内部用权限点（permission code）做鉴权，角色到权限点的映射如下。`✔` = 允许，`△` = 有条件允许，`—` = 拒绝。

| 权限点 | 系统管理员 | 项目管理员 | 开发成员 | 只读访客 |
| --- | --- | --- | --- | --- |
| `user:manage` 用户管理、系统角色分配 | ✔ | — | — | — |
| `system:config` 全局 Jenkins / 凭据配置 | ✔ | — | — | — |
| `project:member` 项目成员与角色管理（RBAC-04） | ✔ | ✔ | — | — |
| `project:config` 项目配置（仓库/Jenkins 绑定、默认参数） | ✔ | ✔ | — | — |
| `build:trigger` 触发构建（`PUBLISH=false`） | ✔ | ✔ | ✔ | — |
| `build:cancel` 取消构建 | ✔ | ✔ | △（仅自己触发的） | — |
| `build:rerun` 重跑 / Replay | ✔ | ✔ | ✔ | — |
| `artifact:download` 下载在线 / 离线产物 | ✔ | ✔ | ✔ | △（仅在线包） |
| `release:publish` 修改发布参数并确认发布 | ✔ | ✔ | — | — |
| `release:rollback` dist-tag 回滚 | ✔ | ✔ | — | — |
| `audit:read` 审计日志读取与导出 | ✔ | ✔ | — | — |
| `ai:invoke` 调用 AI 能力点 | ✔ | ✔ | ✔ | ✔（只读类） |
| `ai:apply:low` AI 低危代执行（重跑、重试核验） | ✔ | ✔ | △（仅自己触发的构建） | — |
| `ai:apply:high` AI 高危建议应用（配置变更，需人审） | ✔ | ✔ | — | — |

约束：**AI 永不代执行发布类动作**（发布、回滚、dist-tag 变更），只能给出建议，这是硬护栏（见 [03](03-backend-design.md) 第 9 节）。

## 6. 三条关键用户旅程

**旅程 A · 每日巡检（项目管理员，2 分钟）**
登录 → 工作台看到"今天 1 次构建失败" → 点进构建列表 → 失败条目定位到构建详情 → 看到失败阶段是 `Artifact Gates` → 点开报告 JSON 看到 SHA-256 不一致 → 用 AI 诊断确认是镜像回源问题 → 触发一次 online 变体重跑。

**旅程 B · 发布一个版本（项目管理员，5 分钟）**
构建列表找到最近一次全变体通过的构建 → 点"发起发布" → 系统跑 REL-01 五项预检（官方仓库、commit 在 master、变体齐全、版本未占用、dist-tag 合规）→ 全部通过后弹二次确认 → 触发发布 → 发布详情实时刷新门禁与链路时间线 → 发布完成看到"回下载 SHA-256 一致 + `latest` 未被改动"。

**旅程 C · 出事回滚（项目管理员，1 分钟）**
收到通知"arm-test 指向的版本 SHA-256 复核失败" → 打开发布详情 → 看 dist-tag 历史 → 点"回滚 dist-tag" → 预览显示将回退到上一版本 → 二次确认 → 执行（通过受控 Job 或复制命令人工执行）→ 审计记录生成。

## 7. 非功能需求

| 类别 | 指标 | 说明 |
| --- | --- | --- |
| 性能 | 列表接口 P95 < 300ms（1 万条构建规模） | 服务端分页 + 索引 |
| 性能 | 构建详情首屏 < 1.5s，日志虚拟滚动 10 万行不卡顿 | 日志分片懒加载 + 前端虚拟列表 |
| 性能 | 日志增量推送延迟 < 3s | SSE + `progressiveText` 轮询 |
| 可用性 | Jenkins 不可达时降级为只读缓存视图，并明示"数据可能过期" | 见 [03](03-backend-design.md) 第 10 节 |
| 可用性 | 平台自身可用性目标 99%（单机 compose 部署） | — |
| 安全 | 平台不落库任何 Jenkins 用户密码 / npm Token | 仅存服务账号 API Token（加密） |
| 安全 | 所有写操作必须留审计，审计 append-only | AUD-05 |
| 安全 | 日志展示前脱敏（token、password、私钥、URL 中的凭据） | 见 [03](03-backend-design.md) 第 9.5 节 |
| 兼容 | 支持浏览 Chrome / Edge 最近两个大版本 | — |
| 国际化 | 中文为默认，文案集中管理，预留 en-US | P2 |
| 可维护 | 前端设计令牌单一来源；后端接口 schema 单一来源（zod → OpenAPI → TS 类型） | 见 [06](06-frontend-design.md) 第 3 节 |
| 数据保留 | 平台侧构建记录保留 200 次（可按项目配置），日志默认保留 90 天 | Jenkins 侧受 `logRotator(20,10)` 限制，平台需自留长历史 |

## 8. 明确不做的事（范围外）

1. 不重写、不解析、不替代 `Jenkinsfile`，不提供"在线编辑流水线"能力。
2. 不做通用 CI 平台（不接管 `witty-ub-build` 等其他项目 Job，除非显式绑定）。
3. 不直接调用 `npm publish` / `npm dist-tag`（不持有 npm Token）。
4. 不回写 Git 仓库：不提供 Agent 启停、注册变更或任何"平台创建 MR"的能力；Agent 启停在仓库改 `ci/agents.json`，平台只读同步（原型中的启停开关与"MR 需审批"字样为旧版遗留，不再实现）。
5. 不做代码托管（不提供 Git 浏览、MR 评审界面），仅链接到 GitCode/AtomGit。
6. 不做 Agent 运行时管理（Agent 装到哪台机器、跑得怎么样，不在本期范围）。
7. 不提供多租户隔离（单组织部署，多项目共享一套 RBAC）。
