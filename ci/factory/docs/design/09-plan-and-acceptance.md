# 09 · 实施计划与验收

## 1. 里程碑

每个里程碑都以"可演示 + 可验收"为完成标准，不做"代码写完但没法看"的阶段划分。

| 里程碑 | 目标 | 交付物 | 关键验收标准 |
|---|---|---|---|
| **M0 脚手架** | 工程可跑通、契约固定 | `ci/factory` 目录树、pnpm workspace、Fastify 骨架、Vue 骨架、zod→OpenAPI→TS 生成链路、compose 起得来 | `make dev` 一条命令起前后端；`/system/health` 返回 ok；OpenAPI 与前端类型一致 |
| **M1 只读视图** | 把 Jenkins 事实搬到平台 | 登录/会话/RBAC 基础、项目与成员、Agent 列表与详情、构建列表与详情、阶段与日志、产物与报告、审计写入 | 能真实读到 `witty-agents-builder` 的构建 #21 并还原 11 阶段、日志、4 个产物；权限矩阵生效（只读访客看不到操作按钮） |
| **M2 写操作** | 平台能驱动流水线 | 触发构建（14 参数抽屉）、取消、重跑、构建导出、通知中心 | 从平台触发一次真实构建并在列表实时看到状态流转到终态；审计可查到 `build.trigger` 与参数快照 |
| **M3 发布管控** | 发布有门禁、有证据、可回滚 | REL-01 预检、发布发起与跟踪、发布详情、dist-tag 历史、回滚流程、`latest` 漂移监控 | 用 smoke Job 真实发布一个 prerelease 版本；门禁 5 项逐项有证据；`latest` 前后快照一致；回滚预览命令可直接执行 |
| **M4 智能与打磨** | AI 能力点与体验完善 | COP-01..05、护栏与审计标记、反馈闭环、SSE 实时日志、性能优化、部署文档 | AI 诊断能在失败构建上给出可跳转的证据链；护栏测试通过（AI 无法代执行发布）；10 万行日志滚动流畅 |

## 3. 测试策略

| 层次 | 范围 | 工具 | 是否必需 |
|---|---|---|---|
| 单元测试 | 参数校验、门禁规则、状态机、脱敏、审计哈希链、报告解析 | Vitest | 必需，覆盖率 ≥ 70%（核心模块 ≥ 85%） |
| 契约测试 | Jenkins 响应解析（用真实响应夹具回放）、registry 响应、Git API | Vitest + fixtures | 必需 |
| 集成测试 | 真实 Jenkins（只读：列构建、拉日志、拉报告） | 可选开关 `RUN_JENKINS_TESTS=1` | 必需（本地/预发执行） |
| 端到端 | 登录 → 看构建 → 触发构建 → 取消 → 发布预检（不真实发布） | Playwright | 必需 |
| 真实写操作 | 真触发一次构建；真跑一次 smoke 发布（用新 prerelease 版本） | 人工执行 | M3 验收时执行一次 |
| 性能 | 1 万条构建列表、10 万行日志、50 并发读 | k6 / autocannon | 必需（M4） |
| 安全 | 权限矩阵用例（4 角色 × 关键接口）、CSRF、越权访问、脱敏 | 自动化用例 | 必需 |

硬性测试要求（对应护栏）：

1. **AI 无发布权限**：构造 AI 代执行请求 → 必须被拒绝（单元 + 接口层双测）；
2. **`latest` 不可被平台改动**：任何接口路径都不应产生对 `latest` 的写操作（代码层禁止 `npm` 写调用，静态检查）；
3. **审计必留痕**：所有写接口的集成测试都要断言产生了一条审计记录。

## 4. 验收清单

### M1 验收（只读）

- [ ] 登录后能看到工作台统计，且数字与 Jenkins 实际一致（对比构建数与成功率）；
- [ ] 项目概览的 Agent 列表与 `ci/agents.json` 完全一致（含 4 个 Agent 的启用状态）；
- [ ] 构建列表能筛选出 `#21` 并展示 `SUCCESS / 1分26秒 / 2026-09-15 20:48`；
- [ ] 构建详情能还原 11 个阶段，其中 `Publish to npm` 显示"未执行（条件阶段）"；
- [ ] 日志中能看到 `Publishing is allowed only from the official repository` 之外的真实错误行（可用 #13/#14/#15 验证），并且没有 ANSI 乱码；
- [ ] 能看到 4 个 Agent 的 online 产物（文件名为 `openeuler-agent-*-online-*.tgz`）；
- [ ] 只读访客登录后，触发/取消/重跑按钮全部不可见。

### M2 验收（写操作）

- [ ] 从平台触发一次 `AGENT=auto / VARIANT=default / PUBLISH=false` 构建，Jenkins 侧确实新增构建；
- [ ] 触发后 5 秒内平台列表出现新构建，状态从 `queued → running → success/failure` 正确流转；
- [ ] 使用相同 `Idempotency-Key` 重复提交不会触发第二次构建；
- [ ] 取消运行中构建后，Jenkins 侧构建显示 aborted，平台状态同步；
- [ ] 审计中存在 `build.trigger` 记录，快照包含完整 14 参数。

### M3 验收（发布）

- [ ] 预检 5 项各自能返回 pass/fail/unknown 与证据字符串；
- [ ] 在仍指向 fork 分支时，预检第 1 项正确判定为 fail 并阻止发布；
- [ ] 切到官方 master 后，预检通过并能触发发布；
- [ ] 发布完成后详情页显示 `latest` 前后一致、候选包与回下载 SHA-256 一致；
- [ ] 人为制造不一致（例如查历史记录）时，页面显示"待人工核查"并给出复核入口；
- [ ] 回滚预览的命令可直接粘贴执行，执行后审计有记录。

### M4 验收（AI 与体验）

- [ ] COP-01 在失败构建上给出根因、证据链（可跳日志行）、建议动作；
- [ ] 未配置 LLM Key 时，所有 AI 面板显示"规则引擎"并提供可用结论（不报错、不假装）；
- [ ] AI 面板的"应用"动作受护栏约束：低危需确认、高危需人审、发布类完全不可执行；
- [ ] 审计页能筛选出所有"用户 × Agent"记录；
- [ ] 10 万行日志滚动帧率 ≥ 50fps，首屏 < 1.5s；
- [ ] SSE 断线后能自动重连续传，不丢行、不重复。

## 5. 风险与对策

| # | 风险 | 影响 | 概率 | 对策 |
|---|---|---|---|---|
| R1 | Jenkins 服务账号权限不足（如 `wfapi` 需要更高权限） | 阶段视图降级为日志解析 | 中 | M0 阶段先用真实账号验证 wfapi 可访问；准备好降级路径（03 §3.3） |
| R2 | `wfapi` 插件缺失 | 同上 | 低 | 同上；必要时在 `ci/jenkins/plugins.txt` 中补齐插件（属 Jenkins 侧变更，需评审） |
| R3 | 两个 Job 仍指向 fork，发布门禁恒 fail | 无法通过平台完成真实发布 | 高 | 这是"暴露真实问题"的预期行为；M3 验收需先把 Job 切到官方 master（属运维动作，见交接手册 §7） |
| R4 | 日志规模增长导致 SQLite 写放大 | 采集变慢 | 中 | 日志分片 + 只在构建结束时批量写；预留 Postgres 切换开关 |
| R5 | AI 幻觉给出错误根因 | 误导排障 | 中 | 强制"阶段性结论"标注 + 证据链可跳转 + 置信度 + 反馈闭环；不用于任何自动决策 |
| R6 | 平台成为新单点 | 平台挂了没法运维 | 低 | 平台只读降级；Jenkins 与命令行仍可独立完成一切操作（平台不是必需品） |
| R7 | 需求蔓延（想接管其他项目 Job） | 工期失控 | 中 | 严格按 01 §8"明确不做"执行；多项目能力保留在模型里但不做界面 |
| R8 | 凭据泄漏 | 安全事故 | 低 | 平台不持有 npm Token；Jenkins/Git Token 加密存库；日志脱敏；审计可追溯 |
