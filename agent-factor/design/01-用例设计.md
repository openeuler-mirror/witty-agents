## 1. 平台定位与范围

面向 witty-agents 生态（可安装到 opencode/witty 的 Agent 包）的 Web 前端平台，覆盖：

| 范围内 | 范围外 |
|---|---|
| Agent 元信息与构建配置管理 | Agent 内部逻辑的深度 IDE 编辑器 |
| 用户 / 角色 / 项目管理（基础 RBAC） | Jenkins 服务自身部署运维（bootstrap.sh 流程仍由运维执行） |
| Jenkins 流水线触发与监控（状态 / 日志 / Artifacts） | npm Token 的创建与分发（仍由管理员在 Jenkins 凭据中维护） |
| npm 发布门禁与结果核验 | npm registry 本身的运维 |
| Agent 详情与安装指引（在线 npm / 离线服务器 artifacts 目录） | Agent 新建/删除（注册以仓库为唯一事实源，v0.5 起） |
| 成功产物下载（在线/离线勾选）与构建记录区间导出（CSV） | 操作审计之外的 BI 报表 |
| 工作台统计图表（每 Agent 构建/下载，饼图+柱状图） | 独立的 AI 助手对话界面（AI 能力全部内联嵌入各功能区） |
| 嵌入式 Agent 能力点（AI 诊断/推荐/建议，附着于各功能区，非独立对话界面） | |

## 2. 角色（Actor）

| 角色 | 说明 | 对应权限锚点 |
|---|---|---|
| 系统管理员 Platform Admin | 平台运营者 | 全局用户/角色、全局 Jenkins 配置、所有项目 |
| 项目管理员 Project Admin | 项目负责人 | 项目内成员、Agent、构建与发布 |
| 开发成员 Developer | Agent 贡献者 | Agent 编辑、触发构建；不可发布、不可管成员 |
| 只读访客 Viewer | 观察者 | 只能查看 |
| 外部系统 | GitCode 仓库、Jenkins、npm Registry | 被动集成对象 |

## 5. 核心用例规约

### 5.1 AGENT-02 新建 Agent（v0.5 已移除）

平台不提供新建 Agent 入口：**Agent 注册以仓库 `ci/agents.json` 为唯一事实源**，新增 Agent 走仓库侧 MR（新增目录 + SKILL.md + `ci/agent.json` + agents.json 注册项），平台定时/手动同步后展示（见 AGENT-01）。此调整避免平台与仓库双写造成的状态分叉。

### 5.2 PIPE-01 参数化触发构建

| 项 | 内容 |
|---|---|
| 参与者 | 项目管理员、开发成员 |
| 前置条件 | 项目 Jenkins Job 连通；目标 Agent 在 agents.json 中 enabled |
| 主流程 | ① 选择构建范围（增量 AGENT=auto / 全量 AGENT=all / 指定 Agent 下拉）→ ② 填写构建参数（表单字段与根 Jenkinsfile 完全对齐，见下表）→ ③ 平台调用 Jenkins `buildWithParameters` → ④ 跳转构建详情页实时展示 |
| 异常流 | a. Jenkins 不可达 → 排队并告警重试；b. 参数组合在 Resolve Build Plan 阶段被拒绝（如 Agent 不支持所选 VARIANT）→ 展示 build-plan 解析错误；c. 同一 Job 已有排队构建（disableConcurrentBuilds）→ 提示排队中 |
| 后置条件 | 产生一条构建记录（编号、触发人、参数、状态、240min 超时基线） |
| 权限 | 开发成员可触发构建；`PUBLISH` 参数仅项目管理员可见/可改（默认 false） |

**构建表单参数（对齐根 Jenkinsfile，共 14 项）：**

| 参数 | 类型/默认值 | 前端处理 |
|---|---|---|
| AGENT | string，默认 `auto`；可选 `auto`/`all`/具体 id（如 shennong-crash） | **构建范围三选一**：增量构建（AGENT=auto，按变更路径前缀）/ 全量构建（AGENT=all）/ 指定 Agent（下拉，数据源=agents.json）（见 PIPE-08） |
| VARIANT | choice：default/online/offline/all | 下拉；选 offline 时联动提示"需 native 节点匹配架构" |
| PACKAGE_STYLE | choice：organization/plain | 下拉，标注 organization 发布 `@openeuler/*` scope 包、plain 发布非 scope 包 |
| TARGET_ARCH | choice：native/x86_64/aarch64 | 下拉，offline 变体联动校验 |
| PYTHON_BIN | string，默认 `python3.11` | 高级选项（默认折叠） |
| PYPI_INDEX_URL | string，默认华为云镜像 | 高级选项 |
| OCR_MODEL_CACHE_DIR | string，默认 `/home/witty-agents-jenkins/ocr-model-cache` | 高级选项 |
| RUN_REAL_INSTALL_VALIDATION | bool，默认 true | 开关，说明真实安装链路（install → setup×2 → configure×2 → remove → stop → uninstall） |
| STRICT_OFFLINE_NETWORK_CHECK | bool，默认 true | 开关 |
| **PUBLISH** | **bool，默认 false** | 仅项目管理员可改；联动 REL-01 门禁 |
| NPM_CREDENTIAL_ID | string，默认 `npm-token` | 管理员级高级项 |
| GIT_CREDENTIAL_ID | string，默认空 | 管理员级高级项；填写后版本自动 bump 回推源分支 |
| NPM_REGISTRY | string，默认官方 registry | 管理员级高级项 |
| NPM_DIST_TAG | string，默认 `latest` | 管理员级高级项；正式发布走 REL-01 校验规则 |

### 5.3 PIPE-03 构建详情与实时日志

| 项 | 内容 |
|---|---|
| 参与者 | 全部角色（访客只读） |
| 前置条件 | 构建记录存在 |
| 主流程 | ① 打开构建详情 → ② 按真实阶段展示 Stage 视图：**Initialize Parameters → Resolve Build Plan → Prepare Agents → Prepare Assets → Install Build Dependencies → Validate Agents → Build Packages → Artifact Gates → Install Contract Checks → Real Install Flow（条件：RUN_REAL_INSTALL_VALIDATION）→ Publish to npm（条件：PUBLISH）** → ③ 日志流式加载（按行缓冲，可下载全量）→ ④ 结束后展示结果摘要与产物链接 |
| 异常流 | a. 日志断连 → 自动重连续传；b. 历史构建日志已被清理（保留 20 次构建/10 次产物）→ 显示归档元数据并提示 |
| 后置条件 | — |

### 5.4 PIPE-08 增量构建（AGENT=auto）

| 项 | 内容 |
|---|---|
| 参与者 | 项目管理员、开发成员 |
| 前置条件 | 以 `AGENT=auto` 触发；本次构建由 commit 变更驱动（pollSCM 或手动） |
| 主流程 | ① 流水线在 Resolve Build Plan 阶段依据 agents.json 各项 `changedPathPrefixes` 与本次 commit 变更路径求交集 → ② 仅命中前缀的 Agent 进入构建计划 → ③ 前端解析 `ci-artifacts/build-plan.json`，展示"计划内 Agent 及命中原因（变更前缀）" |
| 异常流 | a. 无任何 Agent 命中 → 展示空计划并以成功状态快速结束；b. `AGENT=all` 或指定 id → 跳过增量逻辑全量构建 |
| 后置条件 | build-plan.json 归档为 Artifacts |
| 权限 | 同 PIPE-01 |

### 5.5 REL-01 npm 发布（门禁发布）

| 项 | 内容 |
|---|---|
| 参与者 | 项目管理员 |
| 前置条件 | 存在**已通过门禁（Artifact Gates + Install Contract Checks）**的构建产物；目标分支仅受信维护者可写 |
| 主流程 | ① 选择已通过检查的构建 → ② 系统校验（发布前门禁，全部通过才可触发）：**a.** 仓库 origin 必须为官方地址（gitcode/atomgit 的 openeuler/witty-agents）；**b.** 当前 commit 必须包含于 origin/master（非 master 提交阻断）；**c.** 所有本地产物变体全部通过；**d.** 版本为 prerelease（如 `0.10.5-ci.aarch64.0`）且未被占用；**e.** dist-tag 为架构标签（`x86-test`/`arm-test`），**禁止 `latest`** → ③ 弹出 CONFIRM_PUBLIC_PUBLISH 二次确认 → ④ 以 `PUBLISH=true` 触发发布 → ⑤ 展示链路进度：门禁 → 打包 → 发布 → registry 可见性等待 → 回下载 → SHA-256 比对 → ⑥ 全绿则发布成功 |
| 异常流 | a. 版本已占用 → 阻断并自动建议下一版本号；b. dist-tag 非法 → 阻断；c. SHA-256 不一致 → 标记发布失败并告警，提示人工核查 registry；d. `latest` 被误动 → 平台展示发布前后 latest 快照供恢复 |
| 后置条件 | npm 上出现新 prerelease 版本；Artifacts 保存 `ci-artifacts/npm-publish-smoke-summary.json` 与 Agent 的 `artifacts/online-package-report.json` |
| 权限 | 仅项目管理员；发布 Job 权限在 Jenkins 侧同步收紧；npm-token 使用仅限目标包的 granular token |

### 5.6 REL-06 发布回滚

| 项 | 内容 |
|---|---|
| 参与者 | 项目管理员 |
| 前置条件 | 目标包存在历史 dist-tag 指向记录 |
| 主流程 | ① 选择包与待回滚 dist-tag → ② 展示历史指向对比 → ③ 确认后调用 npm dist-tag 切回上一版本 → ④ 平台记录回滚事件并通知 |
| 异常流 | registry 操作失败 → 保留原 tag 并展示错误详情 |
| 后置条件 | dist-tag 指向回滚版本；被弃用版本打"已废弃"标记（不做 unpublish） |

### 5.7 RBAC-05 越权拦截（横切用例）

| 项 | 内容 |
|---|---|
| 参与者 | 全部已登录用户 |
| 主流程 | 前端按角色渲染菜单/按钮（隐藏不可用操作，如开发成员不可见 PUBLISH 参数）；所有 API 后端二次鉴权；越权请求返回 403 并记入审计 |
| 异常流 | 直接调用无权 API → 403 + 审计记录（含用户、时间、目标资源） |

| AGENT-04 | Agent 存在 | 查看 Agent 的版本历史与关联分支/tag | — |
| AGENT-05 | Agent 存在 | **禁用构建（启停）**：对应 agents.json `enabled` 字段开关（禁用=不参与构建计划，不删目录）。v0.3 起平台不提供 Agent 删除操作，归档/清理走仓库侧 MR 流程 | 禁用构建仅项目管理员 |
| AGENT-06 | Agent 存在 | 配置 VARIANT 与 PACKAGE_STYLE 默认值，作为 PIPE-01 表单默认参数 | 修改仅影响后续构建 |
| AGENT-07 | Agent 已注册（仓库侧 MR 合并） | 维护 Agent 目录内 `ci/agent.json`（驱动 run-agent-phase.mjs 各 phase 的配置） | 结构校验（JSON Schema）；v0.5 起与 AGENT-01 同源同步 |
| PIPE-02 | 项目存在 | 构建历史列表（编号、Agent、参数摘要、触发人、状态、耗时），默认保留 20 条在线 | 按状态/Agent/触发人筛选 |
| PIPE-04 | 构建运行中 | 取消运行中/排队构建 | 仅项目管理员或触发者本人 |
| PIPE-05 | 构建已结束 | 以相同参数重跑；一键"重跑失败阶段"（Jenkins Replay） | 重跑产生新构建编号 |
| PIPE-06 | Job 已加载 | 展示 pollSCM（H/5 每 5 分钟轮询）自动构建开关状态与最近自动构建的来源 commit | 自动构建默认 PUBLISH=false，不发布 npm |
| PIPE-07 | 构建有产物 | 按 Jenkins 归档规则列出 Artifacts：`ci-artifacts/**`、`**/artifacts/**`、`**/ci-reports/*.json`（含 build-plan.json、smoke-summary.json），可下载 | 下载链接带权限校验与有效期 |

### 5.9 COP-01 AI 构建日志诊断（嵌入式能力点）

| 项 | 内容 |
|---|---|
| 参与者 | 全部角色（能力显隐跟随日志区查看权限） |
| 前置条件 | 构建详情已打开；日志已加载（含进行中构建的已产生部分） |
| 主流程 | ① 点击日志工具栏「AI 分析」→ ② 日志区顶部**内联展开诊断条**（不弹窗不跳页）：失败阶段定位 + 根因摘要 + 修复建议 + 可回链具体日志行/Stage → ③ 失败 Stage 卡与错误行悬停亦可就地展开同类诊断/解释气泡 → ④ 诊断条可收起，内容带 AI 徽标与有用/无用反馈 |
| 异常流 | a. 构建进行中 → 诊断基于当前已有日志，标注"阶段性结论"；b. AI 服务不可用 → 入口置灰并提示稍后重试；c. 日志被轮转清理 → 提示无法分析 |
| 后置条件 | 若用户采纳"推荐参数重新构建"→ 转入 COP-02 场景 |
| 权限 | 只读访客可用（纯读取分析） |

### 5.10 COP-05 AI Jenkins 配置优化建议（高危人审范例）

| 项 | 内容 |
|---|---|
| 参与者 | 项目管理员 |
| 前置条件 | 位于项目设置/Jenkins 配置区 |
| 主流程 | ① 配置项旁显示「AI 建议」角标 → ② 点击就地展开建议说明 + **变更 diff 预览卡**（旧值→新值）→ ③ 用户点击「应用」后才提交变更（走 MR/配置版本记录）→ ④ toast 回执 + 审计标记"用户 × Agent" |
| 异常流 | a. 建议与当前配置冲突（他人已改）→ diff 卡提示基于版本过期，可刷新重取；b. 用户取消 → 不产生任何变更 |

### 5.11 COP-08 Agent 代理操作护栏与审计（横切用例）

| 项 | 内容 |
|---|---|
| 参与者 | 全部触发 AI 能力点的用户 |
| 主流程 | 按**护栏规则表**执行（见下）；所有 Agent 发起的操作审计记录：触发用户、能力点位置、操作对象、diff/参数快照、执行方式（自动/人审） |
| 异常流 | a. Agent 提议超出当前用户权限的操作 → 前端不渲染执行入口，仅展示建议文本；b. 后端二次鉴权失败 → 403 + 审计 |

**护栏规则表（低危自动 + 高危人审 + 发布仅建议）：**

| 风险级 | 操作 | 执行方式 |
|---|---|---|
| 低危 | 触发构建（PUBLISH=false）/ 重跑 / 取消自己触发的构建 / 一切读取与分析类 | Agent 直接执行，toast 回执，事后审计 |
| 高危 | 修改 Jenkins 配置或参数默认值 / 修改 agents.json 注册信息 / 启用、禁用 Agent 构建 | 页内 diff 确认卡，人审点击确认后才执行 |
| 发布类 | PUBLISH=true / dist-tag 变更 / 发布回滚 | **仅生成建议与操作链接**，用户手动执行，Agent 不代执行 |

## 7. 端到端主流程（业务主线）

```
仓库侧 MR 新增/修改 Agent(目录+SKILL.md+ci/agent.json+agents.json)
→ 平台同步注册表(AGENT-01, 无平台侧新建入口)
→ 配置 VARIANT/PACKAGE_STYLE 默认值
→ 触发参数化构建(增量 auto / 全量 all / 指定 Agent)
→ Stage 监控(11 阶段) + 实时日志(高亮/错误导航)
→ Artifact Gates + Install Contract Checks 通过
→ 成功产物下载(在线 npm / 离线 artifacts 目录勾选) — 使用方支线
→ 选定 online 产物 → 发布门禁(官方仓 + origin/master + prerelease + dist-tag)
→ CONFIRM_PUBLIC_PUBLISH 二次确认(PUBLISH=true)
→ registry 等待 → 回下载 → SHA-256 核验
→ 发布成功 / 失败处理(dist-tag 回滚)
→ 工作台统计图表沉淀(构建/下载次数, 饼图+柱状图)
→ 构建记录区间导出(CSV) — 复盘支线

（可选 AI 增强支线，内联嵌入，无独立界面）
构建失败 → 日志区 AI 诊断(指标卡+证据链+建议+置信度)
→ 采纳建议 → AI 参数推荐填充 → 重新触发 → 门禁通过后走发布主线
```
